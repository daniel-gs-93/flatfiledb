# Paged Execution: Testing Document

## 1. Scope and Environment

- **Design Document:** [PagedExecutionDesignDocument.md](PagedExecutionDesignDocument.md). "Design Document 2.x" and "Design Document 3.x" refer to sections of that document. "ADR-NNNN" refers to an entry in [DecisionRecord.md](DecisionRecord.md), where ADR stands for Architecture Decision Record. "DesignDocument 2.x" refers to sections of [DesignDocument.md](DesignDocument.md).
- **In Scope:** The dependency direction in Design Document 2.1, the types and lifecycle in 2.2, the operator rules in 2.3, the constraint checks and apply in 2.4, the reader-writer lock in 2.5, the equivalence rules and difference table in 2.6, the error mapping in 2.7 and the failure handling in 2.8. The flows and interface in 3.1 to 3.5 are also in scope. Section 2.4 includes the empty change set and the rule that an equal value keeps the stored cell, which also changed the flatfile engine (ADR-0039). Section 2.7 includes a page chain that points past the end of the file.
- **Out of Scope:** Indexes; the Write-Ahead Log (WAL), crash recovery and transactions; the execution of `ALTER TABLE ADD COLUMN` and `DROP TABLE`, where only the `kUnsupported` response is tested; assertions on performance and throughput, since timings are printed and not asserted. Fairness and latency of the reader-writer lock depend on timing, so only mutual exclusion and the correctness of results are tested. The file state left by a process termination (`kill`) is not tested, and no guarantee exists until the WAL and crash recovery are added (Design Document 2.8). Behavior when memory exceeds physical memory, the terminal prompt and interactive input are not tested either. Two known limitations of Design Document 2.8 have no test. One is replacing a paged database whose dirty pages cannot be written out, because a write failure cannot be injected into the real files that `Bootstrap` opens. The other is reopening a directory that was deleted while open. The known limit of Design Document 2.4, a cascade that goes only one level deep, has no test either.
- **Test IDs:** `XU-` is Unit, `XI-` is Integration and `XE-` is Environment. The prefixes differ from `UT-`, `IT-` and `ET-` in [TestDocument.md](TestDocument.md) and from `PU-`, `PI-` and `PE-` in [PagedEngineTestDocument.md](PagedEngineTestDocument.md).
- **Environment conditions:** The Environment tests need the Comma-Separated Values (CSV) files in `data/`, which are not in the repository, and are skipped when the files are missing. XE-02 uses `sample_my_db/`, which is inside the repository. The other tests use only temporary directories and the in-memory `MemoryPageStore`. This document does not record the date, environment or result of a test run.

## 2. Test Strategy

### 2.1 Tiers

| Tier | Boundary Under Test | Real Components | Replaced by Fake or Mock |
|---|---|---|---|
| Unit | The row layer (`operators`, `row_keys`, `mutation_planner`), `ToExecutionError`, the lock of `QueryService` and the dependency direction | The pure functions and classes under test | `IRowStream` and `ITableReader` are implemented over an in-memory `std::vector`, with a version that counts calls. `ICatalog` is replaced by `FakeCatalog`. `IEngine` is replaced by a fake that records the number of concurrent executions |
| Integration | The boundaries across layers: `PagedEngine` plus `Database`, `QueryService` plus the two engines, `Bootstrap`, the `.engine` command and the equivalence of the two engines | The real `PagedEngine`, `Database`, `BufferManager`, `QueryService`, `FlatFileEngine`, `CsvRepository` and `Cli` | `IPageStore` is replaced by `MemoryPageStore`, into which failures and byte rewrites can be injected. The durability tests use real files in a temporary directory. On the flatfile side of the equivalence tests the real `CsvRepository` runs over a temporary directory, so there is no in-memory repository fake |
| Environment | The real data volume of `data/` and `sample_my_db/`, with a buffer pool smaller than the data | The complete system and the existing `FileCsvSource` | None |
