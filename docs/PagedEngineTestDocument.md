# Paged Engine: Testing Document

## 1. Scope and Environment

- **Design Document:** [PagedEngineDesignDocument.md](PagedEngineDesignDocument.md). "Design 2.x" and "Design 3.x" refer to sections of that document. "ADR-NNNN" refers to an entry in [DecisionRecord.md](DecisionRecord.md), where ADR stands for Architecture Decision Record.
- **In Scope:** The formats and rules in Design Document 2.3 to 2.9. They cover the Cyclic Redundancy Check (CRC), the page header and its checks, slots and compaction, tuple encoding, the table heap, the Record Identifier (RID), the buffer pool, the replacement policy, the catalog, file validation and failure handling. The dependency direction in 2.1 and the flows in 3.1 to 3.4 are also in scope.
- **Out of Scope:** The `IEngine` adapter, plan execution and the `.engine` command; indexes; the Write-Ahead Log (WAL) and crash recovery; performance and throughput. The file state left by a process termination in the middle of a flow, for example `kill`, is not tested either. No crash consistency guarantee exists until the WAL and crash recovery are added (Design Document 2.9), so the tests check only that corrupt pages are detected and errors propagate.
- **Test IDs:** `PU-` is Unit, `PI-` is Integration and `PE-` is Environment. The prefixes differ from `UT-`, `IT-` and `ET-` in [TestDocument.md](TestDocument.md).
- **Environment conditions:** The Environment tests read the Comma-Separated Values (CSV) files in `data/`, which are not in the repository, and are skipped when the files are missing. The other tests use only temporary directories and the in-memory `MemoryPageStore`. This document does not record the date, environment or result of a test run.

## 2. Test Strategy

### 2.1 Tiers

| Tier | Boundary Under Test | Real Components | Replaced by Fake or Mock |
|---|---|---|---|
| Unit | The byte layer (`crc32c`, `byte_codec`, `TupleCodec`, `SlottedPage`), the replacement policies, and the boundary between `IPageStore` and `BufferManager`, `TableHeap` and `Catalog` | The classes under test and the pure functions beneath them | `MemoryPageStore` stands in for `IPageStore`, and read, write, allocate and sync failures are injected through it |
| Integration | The database file: `FilePageStore`, `Database`, file format validation, multiple threads, replacement policy switching, dependency direction | Real files in a temporary directory, and the complete paged layer | None, except that one sync failure case goes through `MemoryPageStore`. Corrupt pages, truncation and a version mismatch are produced by rewriting file bytes |
| Environment | The real data volume of `data/` and a buffer pool smaller than the data | The complete paged layer and the existing `FileCsvSource` | None |
